Account and SSH

20 minSkill: setup

  2. git config --global user.name "Your Name"
git config --global user.email "you@example.com"
  3. ssh-keygen -t ed25519 -C "you@example.com"
cat ~/.ssh/id_ed25519.pub
  4. ssh -T git@bitbucket.org
You should see: a message that you are authenticated, with your username.
If it fails: Permission denied (publickey) means the key was not added, or you pasted the private file. Paste only the .pub text.

Branches: create, publish, delete

15 minSkill: branching

  1. git switch -c feature/test-branch
echo "line 2: from branch" >> notes.txt
git commit -am "Add line 2"
git push -u origin feature/test-branch
  2. git switch main
git branch -D feature/test-branch
git push origin --delete feature/test-branch
git branch -a
You should see: the branch gone from git branch -a and from Bitbucket.
If it fails: Cannot delete branch checked out means you are still standing on it. Switch to main first.

Merge conflict with a "teammate"

30 minSkill: conflicts

Clone the repo twice so you can play two developers.

  1. git clone git@bitbucket.org:WORKSPACE/git-practice.git dev-a
git clone git@bitbucket.org:WORKSPACE/git-practice.git dev-b
  2. cd dev-a
git commit -am "A edits line 1"
git push
  3. cd ../dev-b
git commit -am "B edits line 1"
git pull
  5. git add notes.txt
git commit
git push
You should see: git log --oneline --graph showing a merge commit, and clean text with no <<<<<<< in the file.
Panic button: git merge --abort returns you to before the pull. Repeat the lab until you can do it without notes.

Undo toolkit

30 minSkill: fixing mistakes

  1. echo "oops" >> notes.txt
git restore notes.txt            # edit discarded
echo "oops" >> notes.txt
git add notes.txt
git restore --staged notes.txt   # unstaged, edit still there
git restore notes.txt            # now discard it
  2. git commit --allow-empty -m "typo mesage"
git commit --amend -m "Fix message typo"
  3. echo "bad line" >> notes.txt
git commit -am "Bad change" && git push
git revert HEAD
git push
  4. echo "wip" >> notes.txt
git stash
git switch -c temp
git switch main
git stash pop
  5. git commit --allow-empty -m "precious"
git reset --hard HEAD~1
git reflog
git reset --hard HEAD@{1}
You should see: your "precious" commit coming back after the last step.
Remember: never use reset --hard on shared branches. Use revert there.

Versioning: tags and releases

25 minSkill: versioning

  1. npm init -y
git add . && git commit -m "Add package.json" && git push
  2. npm version patch -m "Release %s"
npm version minor -m "Release %s"
  3. git push --follow-tags
git tag
git log --oneline --decorate
  4. git tag -a v2.0.0 -m "Breaking change release"
git push origin v2.0.0
git switch --detach v1.0.1
git switch main
You should see: tags such as v1.0.1 and v1.1.0 in Bitbucket under Branches, then Tags.
If it fails: npm version needs a clean working tree, so commit or stash first.

Pipelines: automatic tests on every push

40 minSkill: CI

  1. echo "module.exports = (a, b) => a + b;" > index.js
echo "const assert = require('assert'); const add = require('./index'); assert.strictEqual(add(2, 3), 5); console.log('tests passed');" > test.js
npm pkg set scripts.test="node test.js"
npm test
  2. image: node:20
pipelines:
  default:
    - step:
        name: Test
        script:
          - npm test
  3. git add . && git commit -m "Add tests and pipeline" && git push
You should see: a green tick for the good commit and a red cross with a readable error for the broken one.
Note: the free plan has a limited number of build minutes per month. Check the current limit in your workspace billing page.

Deploy stages and the capstone

60 minSkill: deployment and full flow

Part A adds staging and production stages. The deploy steps only print a message, which is how the structure works. A real deploy replaces the echo with an upload or a deploy command.

  1. image: node:20
pipelines:
  default:
    - step:
        name: Test
        script:
          - npm test
  branches:
    main:
      - step:
          name: Test
          script:
            - npm test
      - step:
          name: Deploy to staging
          deployment: staging
          script:
            - echo "Deploying build $BITBUCKET_BUILD_NUMBER to staging"
      - step:
          name: Deploy to production
          deployment: production
          trigger: manual
          script:
            - echo "Deploying to production"
Real deployments: store keys as secured repository variables (Repository settings, then Repository variables). Never put passwords or keys in the YAML file or the code.

Part B: capstone (a day on the job). Do all of this without looking at notes:

Confidence check

You are ready for a team repo when you can do each of these without notes:

  • Clone, branch, commit, push and open a pull request.
  • Resolve a conflict, locally and in a pull request.
  • Undo a mistake with restore, amend, revert, stash or reflog, and explain which is safe on shared branches.
  • Tag a release with semantic versioning.
  • Read a failed pipeline log and fix the cause.
  • Explain merge vs rebase, and revert vs reset, out loud.
Repeat labs 5 and 6 once a week until they feel boring. Boring means you are ready.
Practice on throwaway repos only. Bitbucket menus and plan limits change, so check their docs if a screen looks different.
